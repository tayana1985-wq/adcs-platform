## Воспроизведение

Нужен PHP 8.4 CLI. База данных **не** нужна: классы расчёта подключаются напрямую.

```bash
tar xzf ADCS_LIVE_COMPANY_MODEL_SOURCE_51509be.tar.gz     # даст adcs-brain/ и polygon/
python3 tools/ceil.py                                     # потолки, без зависимостей
php tools/probe.php                                       # tap-2 как есть
php tools/probe3.php                                      # tap-3 как есть
```

Скрипты ожидают исходники в `./cp/adcs-brain` относительно себя — поправьте
путь `$B` в первой строке каждого, если раскладка другая.

## Патч

```bash
cd adcs-brain
patch -p1 --dry-run < ../patches/tap-3.1-planning-admissibility.patch   # проверка
patch -p1          < ../patches/tap-3.1-planning-admissibility.patch
php -l src/Analytics/TieAwarePower3.php
php ../tools/verify_patch.php
```

Патч добавляет две величины, которые уже вычислялись внутри, и один отказ:
натяжение альтернативы (`strain = rho_цель / rho_потолок`) и долю повторений,
в которых проверку выполнить нечем. Ни материальность, ни правило Холма, ни
оценка Спирмена, ни требуемая мощность, ни зёрна не затрагиваются; ни одно уже
напечатанное пригодное `N` не меняется.

Пороги `MAX_ASSOCIATION_STRAIN = 0.60` и `MAX_NOT_EXECUTABLE_SHARE = 0.02`
помечены в коде статусом `THRESHOLD_DECLARED_NOT_APPROVED`: числа объявлены, а
не выведены, и подлежат отдельному решению владельца продукта — как Δθ.
Механизм отказа работает при любых утверждённых значениях.

## Главное в одну строку

Проверенный и не закрытый авторами дефект один: в tap-2/tap-3 требуемое `N`
наименьшее там, где моделируемая альтернатива почти детерминирована (натяжение
0.967 от потолка), а проверка расхождения четырёх конструкций связи даёт на этой
строке согласие выше, чем на здоровых. Патч добавляет два отказа.
